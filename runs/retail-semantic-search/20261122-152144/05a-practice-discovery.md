## Where public sources contradict the model

### P04: Do not automatically carry Amazon DocumentDB's retryWrites=false workaround into Azure DocumentDB, because the Azure migration guide says to remove it, although Azure vector-search quickstarts explicitly require the same setting.

- **The model believed:** Set retryWrites=false in the MongoDB connection configuration to avoid retryable-write protocol incompatibilities. (knowledge of `amazon_documentdb`)

## Notes

Read-only investigation: no files, database data, indexes, or Azure resources were changed; no scripts or live database operations were run. Read the main configuration, client, catalog, ingestion, repository, recommendation, memory, model, CLI, seed, and verification files, plus package.json and README.md. The app uses mongodb 6.22.0, a LlamaIndex function agent with a custom driver retrieval tool, 20,000 deterministic orders, 60 separately embedded products, 1536-dimensional OpenAI embeddings, DiskANN, array-field co-purchase aggregation, and process-local bounded session memory. It does not provision clusters or implement persistent memory, full-text search, local containers, or cross-region replication. Relevant means the area affects the app, not that it passes the recommendation.

Open discovery preceded the belief-specific searches. The result contains 21 additional public practices and all 25 beliefs exactly once; overlapping discovery findings were reused. All reachable source channels were used: Learn search/fetch and relevant installed skills/resources. Only the Learn MCP server was available; repository links were surfaced but no repository-reading tool was available. Local app comments and README claims were not treated as independent public confirmation.

Belief results: 11 confirmed, 1 contradicted, 13 prior-knowledge-only. Confirmation reflects the underlying recommendation, not an exact match to illustrative collection names or the 20,000-record count. K07 is supported explicitly by the indexing skill's natural-key guidance; this app already uses business IDs as _id. K09 is explicit in the LangGraph documentation and both connection skills. K10's complete certificate-and-hostname rule is explicit in the security skill; public security and migration-connectivity documentation also support TLS and certificate verification. K12 combines the Azure CLI page's explicit source-control prohibition, the Azure migration guide's Key Vault recommendation, and the LlamaIndex page's environment-based model credentials. K15 includes the transient-fault guide explicitly endorsed and linked by the Azure DocumentDB reliability page; that linked guide supplies jitter and terminal-error exclusions. K16's TypeScript example uses sequential bounded insertMany batches, not bulkWrite specifically; the service limits separately document bulk-operation support and a maximum of 25,000 writes per request.

Partial support was not promoted to full confirmation for compound beliefs: K03 has documented M30+ support but no discovered DiskANN-specific server-version gate or fail-without-fallback rule; an agent quickstart instead says M40+. K05 has model/dimension consistency guidance but no finite-number rejection guidance. K06 has generic embed/reference guidance, including text under the former Azure Cosmos DB for MongoDB vCore name, but no discovered product-versus-order embedding prescription. K11 has awaited connect/ping examples and configuration checks, but no complete startup-validation and credential-redaction contract. K14 has scenario-specific driver timeouts and a documented maxTimeMS override of the default 120-second query limit, not a universal requirement to set every listed timeout. K17 has stable-ID upsert examples and $setOnInsert compatibility/semantics, but no discovered deterministic transaction-seeding recommendation. K19 has aggregation operators and early-filter guidance, not distinct-per-order co-purchase correctness. K20 has selective projection examples, not the full response/LLM privacy rule. K21 has session/thread persistence examples, not authenticated ownership plus history/lifetime enforcement. K22 has retrieved-data grounding, not ranked-ID membership validation. K23 has name-based idempotent creation, index listing, and readiness retries, not definition-drift comparison. K24 has model/dimension/version and re-embedding guidance in the vector skill, but no service-specific content-hash lifecycle recommendation. Searches returning these partial building blocks are recorded in how_found rather than described as wholly empty.

The main contradiction is itself unresolved in the public record: the Azure migration guide explicitly tells developers to remove Amazon's retryWrites=false setting, while the fetched TypeScript vector quickstart explicitly says retryWrites=false is required for DocumentDB vector search, and the native-auth quickstart includes it. The deployment skill claims retryable writes are unsupported, whereas driver/security skill examples set retryWrites=true. P04 therefore records contrary guidance, not a conclusion that this app should enable retryable writes.

Other discoverability and consistency issues: vector documentation generally says M30+, while the agent quickstart says M40+; the LlamaIndex how-to says its vector-store connector is Python-only, while the integration overview lists JavaScript support without that distinction. The HA skill describes only customer-triggered regional promotion, but fetched documentation now includes opt-in service-managed failover. Secondary-user documentation describes preview database/collection-scoped custom roles, while the limits page still says only cluster-level scope is supported. The diagnostics how-to excludes M30 and lower, while broader pages only exclude free tier. The limits page says sorting is in memory, while ordered-index documentation and explain guidance describe sort pushdown. These conflicts were not silently resolved using model memory. Some broad searches also returned Cosmos DB RU guidance and misleading Q&A advice about RU scaling; those were excluded as Azure DocumentDB evidence.
