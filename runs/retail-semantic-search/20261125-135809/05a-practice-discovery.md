## Notes

Read the main implementation files, ingestion and verification scripts, package manifest, and README; this is a sequential Node.js CLI using MongoDB 6.22, native SCRAM, OpenAI embeddings, 120 product vectors, 20,000 separate orders, DiskANN, indexed co-purchase aggregation, and in-process LlamaIndex memory. No files, infrastructure, or database data were changed. Used both reachable source classes: Learn search/fetch and relevant installed skills/resources; no DocumentDB database MCP or general repository-fetch tool was available. Open discovery preceded all 25 belief-specific searches. The result contains 30 retained open-discovery recommendations, 15 merged with prior beliefs, plus 10 belief-check entries. All beliefs appear exactly once: 16 confirmed and 9 prior-knowledge-only; no clear contradiction of a fixed belief was established. Confirmation means the recommendation is supported, not that the app complies. Relevant includes service configuration the app depends on, even when provisioning is external. Partial evidence was deliberately not promoted to full confirmation: K05 has numeric-array/dimension guidance but not the complete finite-value rejection contract; K06 has skill guidance for model metadata/backfills/index rebuilding but not the complete model-version/input-construction contract; K08 has general MMR and compression oversampling but not this co-purchase/session ranking recipe; K09 has general embedding/reference guidance but no canonical retail-vector design; K15 has ping, timeout, and troubleshooting examples but no complete startup validation/error contract; K18 has bulk support and a 25,000-writes-per-request limit but no bounded-concurrency ingestion recommendation; K20 has early-filter and server-side aggregation guidance but no complete co-purchase sequence; K22 has session/thread identifiers and TTL building blocks but no complete isolation/history/expiration policy; K25 has grounding guidance but not the full evidence-and-untrusted-text policy. Searches listed as unhelpful returned related material, but no source establishing the complete belief. Public-record inconsistencies matter: the main vector guide says DiskANN M30+, whereas the TypeScript agent quickstart says M40+; deployment/connection skills assert retryWrites=false and no retryable-write support, but driver/security skill examples set retryWrites=true and current ORM tutorials call false a sample setting requiring deployment verification. K03 remains confirmed as conditional conservative guidance, not as proof that retryable writes are universally unsupported. Scoped custom roles are documented as preview with CRUD-only privileges, while the limits page still says roles are cluster-scoped; K16 therefore requires feature verification. K19's jitter guidance comes through the general transient-fault guide explicitly mandated by the Azure DocumentDB reliability page. Former Cosmos DB for MongoDB vCore wording was accepted only for this same service, never for RU-based Cosmos DB. Installed skill guidance was retained as skill evidence even when its cited reference was MongoDB-only; that reference alone was not treated as Azure service confirmation.
